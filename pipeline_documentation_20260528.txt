================================================================================
0. WHAT CHANGED FROM THE 2026-04-14 VERSION (read this first)
================================================================================

This pipeline differs from the original single-bucket version on two axes:

1. BRAND-BUCKET ISOLATION
   The raw dataset is first split into 6 INDEPENDENT buckets (gender x brand
   tier). Every embedding / training / analysis step runs SEPARATELY per
   bucket. Mixing categories pollutes embedding weights and produces
   uninterpretable elasticities for any single subgroup.

     Women x top1  -> women_top1_dream_pairs
     Women x top2  -> women_top2_idifu
     Women x other -> women_other
     Men   x top1  -> men_top1_bruno_marc
     Men   x top2  -> men_top2_nike
     Men   x other -> men_other

   Hard rule: no bucket reads another bucket's predictions, embeddings, or
   model weights. The only intentionally shared artifacts are:
     - data/images/{ASIN}.jpg          (raw product photos, ASIN-unique)
     - data/_shared/vartheta/...csv    (category-level Pareto shape theta)

2. STRATIFIED SPLIT MOVED UPSTREAM (00_part2b DELETED)
   The old 00_part2b_embed_cluster_split.ipynb (frozen RoBERTa + BEiT + SAINT
   -> PCA -> KMeans -> cluster-stratified split, A100 required) has been
   REMOVED. The split is now decided cheaply, before any data_preparation
   step, by brand_split/01_stratified_split.ipynb:
     - stratify on subcat_aggregated x SALES_RANK quartile, within each bucket
     - strata with < 4 ASINs merge into OTHER_SMALL
     - no GPU, runs in seconds, no leakage (keys are product attributes)
   The assignment is materialized into per-bucket train/val parquets at the
   TAIL of 00_part1.

3. theta IS SHARED, NOT PER-BUCKET
   The Pareto shape parameter theta (converts rank-elasticity to demand-
   elasticity) is a structural parameter of the CATEGORY (shoes). Estimate it
   once via code/estimate_vartheta_shoes.ipynb and reuse for all 6 buckets.

PER-BUCKET PARAMETER
   Every per-bucket notebook has ONE line to edit near the top, inside the
   cell with id 'bucket-output-config':
       BRAND_BUCKET = 'women_top1_dream_pairs'   # change per bucket run
   All other paths (DATA_ROOT, DATA_DIR, ANALYSIS_DIR, KEY_DIR, PRED_DIR,
   OUTPUT_DIR, IMG_DIR) derive automatically from BRAND_BUCKET via a
   _find_project_root() helper. No /content/ or Google Drive paths remain in
   code/ - the pipeline runs locally (PyCharm Jupyter or nbconvert).

PHASE 0 - DATASET COLLECTION FROM KEEPA API (historical, run once)
================================================================================

WHAT IS KEEPA
  Keepa is a third-party Amazon price tracker storing historical data for
  millions of products. It exposes a REST API for product metadata, price
  history, sales rank history, Buy Box data, ratings, review counts. Amazon
  does not provide historical sales data directly, so Keepa is the source.

  API endpoint : https://api.keepa.com
  Domain       : 1 (Amazon US)
  Cost         : 4 tokens per ASIN (1 base + 1 rating + 2 Buy Box)
  Token refill : 20 tokens per minute on paid plan

HOW THE DATA WAS PULLED - 7 BATCH NOTEBOOKS
  Pulled in 7 batches by sales rank range (limited Colab runtime + Keepa rate
  limits made one-shot infeasible):

  amazon_shoes_8_batch1.ipynb   Rank       1 -  10,000
  amazon_shoes_8_batch2.ipynb   Rank  10,001 -  20,000
  amazon_shoes_8_batch3.ipynb   Rank  20,001 -  30,000
  amazon_shoes_8_batch4.ipynb   Rank  30,001 -  40,000
  amazon_shoes_8_batch5.ipynb   Rank  40,001 -  60,000
  amazon_shoes_8_batch6.ipynb   Rank  60,001 -  80,000
  amazon_shoes_8_batch7.ipynb   Rank  80,001 - 100,000

  Date window (all batches):
    START_DATE = '2025-01-01'
    END_DATE   = '2026-03-31'
    DAYS       = 454

KEEPA FILTER PARAMETERS (applied in all batches)
  categories_exclude : [679320011, 679365011, 679378011, 679433011]
                       Exclude Costumes, Accessories, unrelated categories
  title              : 'shoes'           Must contain the word shoes
  rootCategory       : ['7141123011']    Amazon Shoes root category only
  type (exclude)     : sandal, shoelace, slipper
  brand (exclude)    : crocs, flip*flop
  outOfStockPercentage90_BB_gte: 1       Had some out-of-stock time (active)
  outOfStockPercentage90_BB_lte: 80      Not perpetually out of stock
  trackingSince_lte  : 7364640           Anti-backfill guard - tracked pre 2025
  productType        : [0, 1, 2]         Physical products only
  size               : ['8']             Size 8 only

  NOTE: a leading exclude-marker before type/brand values is Keepa's syntax
  for excluding those values.

WHAT EACH BATCH NOTEBOOK DOES
  Input  : Keepa API (live HTTP, no local input file)
  Process:
    1. Query Keepa Finder API with SELECTION filter -> matching ASIN list
    2. Paginate (100 ASINs/page), cache ASIN list to .txt (resume on crash)
    3. For each batch of 100 ASINs call Product Data API:
       stats=1, rating=1, buybox=1, offers=0
    4. Expand daily history into weekly rows: window=7 and window=28 rolling avg
    5. Log transforms:
       SALES_RANK   = log(1 / sales_rank)
       PRICE        = log(avg_price)
       BUYBOX_PRICE = log(avg_buybox_price)
    6. Metadata: text = title|manufacturer|brand|model|color|size ;
       subcat = leaf category ; image = first image URL
    7. Save batch parquet

COMBINE STEP (amazon_shoes_8_combine.ipynb)
  Concatenate all 7 batch parquets, dedupe on (ASIN, date, window), sort, trim
  weekly-binning overshoot past Mar 31.
  OUTPUT: amazon_shoes_8_combined.parquet
    ~1,008,930 rows | 7,761 ASINs | 27 columns | Jan 2025 - Mar 2026
    Genders: Women (5,472), Men (2,279), Costumes (9), Accessories (1)

  In the current repo this combined file is the single raw input, placed at:
    data/amazon_shoes_8_combined.parquet      (not committed - ask Billy)

PHASE 2 - DATA PREPARATION (run for EACH of the 6 buckets)

Location: data_preparation/   | edit BRAND_BUCKET at the top of each notebook.

--------------------------------------------------------------------------------
NOTEBOOK: 00_part1_data_preparation.ipynb              CPU
--------------------------------------------------------------------------------
INPUT
  data/<bucket>/amazon_shoes_8_combined.parquet
  data/<bucket>/keys/asin_split.csv   (from brand_split/01)

OUTPUT (all under data/<bucket>/)
  amzn_shoes_monthly_diffs_ffill_fixed_splits/all_products_clean.parquet
  amzn_shoes_monthly_diffs_ffill_fixed_splits/train-00000-of-00001.parquet
  amzn_shoes_monthly_diffs_ffill_fixed_splits/validation-00000-of-00001.parquet
  keys/main_train_keys.csv
  keys/main_val_keys.csv

PROCESS
  1. Load bucket parquet, parse dates
  2. Remove dirty ASINs (wrong gender/size, fully-NaN SALES_RANK/PRICE/
     RATING/REVIEW_COUNT)
  3. Drop 9 unused columns: SALES_RANK_original, PRICE_original,
     BUYBOX_PRICE_original, gender, manufacturer, brand, model, color, size
  4. Fix dtypes: window to float64, FBA/FBM offer counts filled with 0
  5. Rebuild subcat_aggregated from top-10 subcategories; all others -> "Other"
  6. CRITICAL - fill BEFORE trim:
       Jan/Feb 2025 rows act as a forward-fill seed for March.
       BUYBOX_PRICE: ffill then bfill (products that gained a Buy Box mid-window
         have leading NaN with no prior value to carry forward; bfill carries
         the first known price backward).
       All other columns: ffill only.
  7. Trim to analysis window (date >= 2025-03-01)
  8. NaN-flag columns on the trimmed window (is_*_filled)
  9. Drop incomplete ASINs:
       BUYBOX_PRICE: drop only if 100% NaN over the year (threshold 0.999)
       Other columns: drop if any NaN remains after fill
 10. Reorder to 17-column paper schema, drop flag columns, save clean parquet
 11. TAIL STEP - apply the pre-computed stratified split:
       load keys/asin_split.csv, subset all_products_clean by split assignment,
       write train / validation parquets + main_train_keys.csv / main_val_keys.csv.
       Reports how many split-assigned ASINs were dropped by cleaning.

  Example (women_top1_dream_pairs, tested end-to-end):
    447 ASINs -> 442 after cleaning -> Train 221 ASINs / Val 221 ASINs,
    25,194 rows each.

OUTPUT PARQUET COLUMNS (17)
  ASIN, window, date, SALES_RANK, PRICE, BUYBOX_PRICE, text, RATING,
  REVIEW_COUNT, subcat, subcat_aggregated, New Offer Count: Current,
  Count of retrieved live offers: New FBA,
  Count of retrieved live offers: New FBM,
  Lightning Deals: Upcoming Deal, Buy Box: Is FBA, image

INPUT  : data/<bucket>/amzn_shoes_monthly_diffs_ffill_fixed_splits/ (ASIN + URL)
OUTPUT : data/images/{ASIN}.jpg     (SHARED across buckets, keyed by ASIN)

INPUT  : data/images/{ASIN}.jpg
OUTPUT : data/<bucket>/amzn_shoes_monthly_avg_long_ffill_28_7_images/

--------------------------------------------------------------------------------
NOTEBOOKS: 00_part3a / 3b / 3c / 3d - embedding model training   GPU (A100)
--------------------------------------------------------------------------------
THE 4 VARIANTS (one notebook each, to fit Colab/GPU session limits)
  3a: txtimg + lag1          Text+Image+Tabular, lag-1 time features
  3b: txtimg + time_ind      Text+Image+Tabular, no lag
  3c: txt + lag1             Text-only, lag-1 time features
  3d: txt + time_ind         Text-only, no lag

INPUT
  data/<bucket>/amzn_shoes_monthly_diffs_ffill_fixed_splits/ (train + val)
  data/images/{ASIN}.jpg  (3a, 3b only)
OUTPUT
  data/<bucket>/predictions/txtimg/{lag1,time_indipendent}/   (zips)
  data/<bucket>/predictions/txt/{lag1,time_indipendent}/      (zips)

MODEL ARCHITECTURE (Bach et al. 2025, Appendix G)
  Text encoder    : RoBERTa (cardiffnlp/twitter-roberta-base) -> 768
  Image encoder   : BEiT (microsoft/beit-base-patch16-224)    -> 768
  Tabular encoder : SAINT (pytorch-widedeep 1.7.0)            -> 768
  Fusion          : LayerNorm -> Cross Attention -> FC -> 256-dim embedding
  Heads           : FC -> Q_hat (SALES_RANK), FC -> P_hat (PRICE)
TRAINING CONFIG
  WINDOW=28, MOD=4, MAX_PERIODS=53, BATCH_SIZE=32
  EPOCHS_LEVEL=25 (predict Q_t, P_t), EPOCHS_DIFF=15 (predict dQ_t, dP_t)
  LR=2e-5, EMB_DIMS=[128, 256], AdamW + cosine annealing
  These 4 notebooks are the ONLY GPU stages. 4 variants x 6 buckets = 24 runs.

--------------------------------------------------------------------------------

================================================================================
KEY VARIABLE DEFINITIONS
================================================================================
Q_t          = SALES_RANK = log(1/sales_rank) - quantity/demand signal
P_bb_t       = BUYBOX_PRICE = log(buy_box_price) - treatment (price)
Delta_Q_t    = Q_t - Q_{t-1}   (first difference of quantity)
Delta_P_bb_t = P_bb_t - P_{t-1} (first difference of price)
window=28    = 28-day rolling average (used for modeling)
mod=4        = every 4th time step (approximately monthly)
pred_ml_l    = level model prediction for Q_t
pred_ml_m    = level model prediction for P_bb_t
_diff suffix = diff model prediction for Delta_Q_t / Delta_P_bb_t
_lag_1       = from the lag-1 model variant
emb_0..255   = 256-dim product embedding from the fusion model
pca_0..4     = first 5 PCA components of embeddings
similarity_cluster_0..4 = cosine similarity to each KMeans centroid
theta_price  = price elasticity of demand (key causal estimate)
theta (Pareto) = shape parameter converting rank-elasticity to demand-elasticity
ATE          = Average Treatment Effect (avg theta_price across products)
CATE         = Conditional ATE (theta_price per cluster)


================================================================================
NOTES ON PAPER FIDELITY
================================================================================
Follows Bach et al. (2025) arxiv 2501.00382. Intentional differences:

1. Dataset : Amazon Shoes Size 8 (Jan 2025 - Mar 2026), split into 6
             gender x brand-tier buckets, vs Amazon Toy Cars (2023-2024).
2. Batches : 7 batches by sales rank range 1-100,000.
3. Split   : cheap upstream stratified 50/50 (subcat x SALES_RANK quartile per
             bucket), decided before data_preparation. The earlier embedding-
             cluster split (00_part2b) was removed. Paper used 80/20.
4. BUYBOX fill: ffill + bfill for BUYBOX_PRICE (vs ffill only).
5. theta   : shoes-specific Pareto theta estimated on the full dataset and
             shared across buckets, NOT the paper's toy theta ~ 0.5.

Reference repo: github.com/JanTeichertKluge/demand-analysis-repro
