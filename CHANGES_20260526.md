## 2. `brand_split/` — new upstream split step

- ➕ Created `brand_split/01_stratified_split.ipynb`
  - Loops over all 6 buckets in one pass
  - Stratification axis: `subcat_aggregated × SALES_RANK quartile`, computed **within each bucket**
  - Strata with < 4 ASINs merge into `OTHER_SMALL`
  - Writes `code/<bucket>/asin_split.csv` (columns: `ASIN, stratum, split`)
  - No GPU required, runs in seconds

**Why:** replaces the previous embedding/cluster-based split with a cheap, leakage-free upstream alternative. See [Stratified split design](.claude/projects/-Users-yvony-PycharmProjects-Amazon-demand-analysis-seperate/memory/stratified_split_design.md).

## 6. Design principles persisted to memory

1. **Per-bucket embedding isolation** — every embedding/model training step runs separately per bucket. Mixing categories pollutes weights; the 6 buckets are a hard isolation boundary.
2. **Stratified split design** — train/val split decided upstream in `brand_split/01`, using cheap `subcat × SALES_RANK quartile` (not embedding-based clusters).
3. **Shoes ϑ calibration** — paper's toy ϑ (≈0.5) does NOT apply. Use shoes-specific ϑ from `estimate_vartheta_shoes.ipynb` (Approach A ϑ̂ = 0.875). **ϑ is shared across all buckets** (category-level structural parameter, not per-bucket).
4. **Local-only workflow** — user never uses Colab Drive. Stale `/content/drive/...` paths in notebooks are vestigial; always derive paths from `PROJECT_ROOT`.
